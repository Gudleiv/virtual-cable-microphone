# Endpoint survey — 2026-08-12

Condensed from `vcmic --list-devices` on the target machine (45 render and 26
capture endpoints, most of them `NOTPRESENT` ghosts from earlier hardware).
Only what matters for the routing is kept here.

## The three endpoints vcmic uses

| Role | Friendly name | Endpoint id | Format |
|---|---|---|---|
| chat loopback source | Наушники гарнитуры (Sound Blaster GC7) | `{0.0.0.00000000}.{d08ae5da-995b-4f0e-8adb-ac19ddc87bf0}` | 48000 Hz, 2 ch, float32 |
| microphone | Микрофон (4- fifine Microphone) | `{0.0.1.00000000}.{07e3bc09-e84c-412f-a7bd-290bca23d211}` | 48000 Hz, 2 ch, float32 |
| cable input | CABLE-A Input (VB-Audio Virtual Cable A) | `{0.0.0.00000000}.{4367dfca-8893-49ed-80fd-c740a21c9cb9}` | 48000 Hz, 2 ch, float32 |

ShadowPlay records the capture side of the same cable:
**CABLE-A Output** `{0.0.1.00000000}.{a789742f-ab35-41b1-b651-1c86c68a1787}`
(48000 Hz, 2 ch, float32).

All three run at 48 kHz, so no resampler is needed and the strict sample-rate
check in the config can stay on. Minimum device period is 3 ms on the GC7
endpoints and 2 ms on the cable; default period is 10 ms everywhere.

## Sound Blaster GC7 endpoints

| Endpoint | Flow | State | Roles |
|---|---|---|---|
| Динамики | render | ACTIVE | Console, Multimedia — the game, and ShadowPlay's system track |
| Наушники гарнитуры | render | ACTIVE | Communications — Discord |
| Лин. вход | capture | DISABLED | |
| **What U Hear** | capture | **DISABLED** | |
| Микрофон | capture | **DISABLED** | |
| Цифровой вход | capture | DISABLED | |

Two of these contradict assumptions in the specification:

- **What U Hear exists.** Section 1 of the spec states the GC7 has none. The
  endpoint is present and merely disabled in Windows. It does not change the
  design: What U Hear captures the device's own output mix, which on this card
  includes the game, so using it for the microphone track would put the game
  audio into both recorded tracks. Loopback of the chat endpoint stays the
  correct source. It is worth knowing it exists, though.
- **The GC7 microphone input is disabled**, so the microphone in the signal
  chain is the standalone USB fifine, not the GC7's own input.

## Microphone situation

`Микрофон (4- fifine Microphone)` is the default Console, Multimedia *and*
Communications capture device, so it is what Discord opens. It is the only
physical microphone that is ACTIVE; the remaining active capture endpoints are
virtual (Oculus, DroidCam at 16 kHz, and the two cables).

The `4-` prefix is Windows' counter for the same USB device seen on a fourth
port — `fifine`, `2- fifine`, `3- fifine` are all `NOTPRESENT` leftovers.
Replugging into another port creates a fifth endpoint with a new id, which is
why `mic_capture_name = "fifine"` is set as a fallback: only one of them is
ever ACTIVE, so the substring match is unambiguous in practice.

## Cables

VB-Audio Virtual Cable A and B are both installed, and each exposes two render
endpoints — `CABLE-x Input` and `CABLE-x In 16ch` — plus one capture endpoint,
`CABLE-x Output`. vcmic writes to `CABLE-A Input`; cable B is untouched and
stays available for anything else.
